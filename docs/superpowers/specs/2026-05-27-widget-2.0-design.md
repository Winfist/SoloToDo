# SoloToDo Widget 2.0 — Design Spec

Date: 2026-05-27
Status: Approved (design), implementation in progress

## Goal

Elevate the iOS home-screen widgets from "okay" to a premium, full, crafted "Hunter
Dashboard". Four concrete drivers from the user:

1. **Edge-to-edge** — kill the inset "Quadrat" card; fill the whole widget.
2. **Micro-Habits get their own treatment** — they are counters (3/8), not quests, so
   they must not reuse the quest-row layout.
3. **2.0 look with the app's own icons** — use the real `.webp` icon art, full-color.
4. **Mode/size polish** — quests-only mode should pack as many quests as fit, with paging.

Design constraints (see memory `premium-minimal-design-pref` / `widget-visual-direction`):
one accent + neutral chrome, NO neon-glow chrome, NO rainbow. But: **icon artwork keeps
its original colors**, and the layout must feel **rich/full**, not sparse.

## Design system

- **Surface**: edge-to-edge dark glass. Layered background = base gradient
  (`#101424 → #05060d`) + a single soft top accent sheen + a faint vignette + very subtle
  grain for material depth. Concentric/hexagon motif watermark at ~5% opacity.
- **One accent** = `data.theme.primary` (theme-driven). Used for XP bar, progress rings,
  focus spine, page indicator, chevrons. Everything else neutral slate.
- **Typography**: serif (Cinzel-substitute) for hunter name; sans (Outfit-substitute) for
  content; mono (JetBrains-substitute) for numbers + section kicker.
- **Icon tiles**: rounded-square (radius 9) faint-fill tile holding the real full-color
  icon. Tile border picks up the quest's **difficulty color** (boss=violet, hard=orange,
  normal=cyan, easy=green) at low alpha — semantic, not rainbow.
- **Rings**: progress gauge (accent stroke) with the real icon centered — the shared
  language for micro-habits and quest progress.

## Layouts

### Header (all sizes, scaled)
Rank sigil (hexagon + rank letter) · serif name · level · streak (flame) · gold/gems.
Thin XP bar + `xp/needed` mono number. On Large add the hunter title.

### Quests mode
- **Small**: one focus quest — full-color difficulty icon as hero (+ faint watermark),
  title, next step, streak, fraction, mini XP bar.
- **Medium**: exactly **2 quests** (header must stay compact so both fit). Each row:
  difficulty-tiled icon, title, next step, progress ring, fraction. Focus row gets the
  accent spine + faint gradient. Page indicator (dots) + chevron.
- **Large**: **6 quests per page** (no stats/micro section in quests-only mode), each with
  a difficulty meta label (BOSS/HARD/…). Bottom "SEITE x/y · TIPPE ›" pager.

### Micro-Habits mode
Row of ring-gauges (Medium: 4 across; Large: 5 + larger): accent progress ring + real
`micro_*` icon centered + label + `current/target` mono. Header shows "n/total heute".
**No quest-style rows.**

### Mix / dashboard (Large default)
Quests (3) + micro ring row + STR/INT/VIT/AGI/CHA stat footer — the full glance.

## Interaction (existing intents, now made legible)
- **Page**: chevron (top-right, with "1/2") advances the page in the current mode
  (`AdvanceWidgetPageIntent`). No app launch.
- **Expand stages**: tapping a quest toggles its Etappen inline as a checklist
  (`ToggleQuestExpandIntent`); tap again collapses.
- **Open**: tapping the title / "In App öffnen" deep-links into the quest.

## Data changes (`services/widgetDataService.js`)
- **Own quests first**: sort so user-created (non-system) quests always rank above system
  quests, then apply the existing focus/priority ordering within each group.
- Micro-habit `icon` defaults already align to `micro_<id>`; ensure each emitted
  micro-habit carries an icon key the widget can map (water/stretch/breathe/gratitude;
  posture needs an icon or a documented fallback).

## Configuration (widget edit screen)
`SoloToDoWidgetConfigurationIntent`:
- `mode`: Quests / Habits / Micro-Habits / Mix (existing).
- **`background` (new)**: Auto / Dunkel / **Transparent**. Transparent renders a
  frosted/translucent container (`.ultraThinMaterial`-style) so the wallpaper shows
  through; default stays the dark glass.

## Icon system
Bundle a curated subset of `public/icons/*.webp` into the **widget target** (asset catalog
`WidgetIcons.xcassets`). Mapping helpers:
- quest → `diff_<difficulty>` (fallback `quest_<type>`).
- micro-habit → `micro_<id>`.
- habit → `habit_<category|verification>`.
Only transparent-background icons are widget-safe inline; baked-background art
(habit_fitness, crest, …) is reserved for large hero placements only.
Render full-color (original colors); chrome stays one-accent.

## Theming
Accent + sheen derive from `data.theme` (already synced from the app, incl. custom themes).
Transparent is orthogonal (a background-style config, not an app theme).

## Non-goals
- The widget never completes tasks (view + deep-link only); completion stays in the app.
- No live/animated effects beyond static gradients.

## Implementation order
1. Data: own-quests-first sort (JS). ✅ low risk
2. Edge-to-edge: `.contentMarginsDisabled()` on widget configs.
3. Quests density: Large pageSize 4 → 6.
4. Transparent background config option + container rendering.
5. Icon asset catalog in widget target + mapping helper + render in tiles/rings.
6. Micro-Habits ring view (replace `TaskListRow` for micro mode).
7. Visual polish: difficulty colors, rank sigil, currencies, page dots, vignette/grain,
   focus spine glow.

Build + on-device verification happen on macOS/iPhone (cannot build iOS from the dev box).
