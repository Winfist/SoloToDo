# Schmiede 2.1: iPhone-Hotfix + Polish

**Datum:** 2026-07-20
**Status:** Entwurf
**Anlass:** iPhone-Test des Users nach Schmiede-2.0-Deploy — Accept wirkungslos, X unerreichbar, Hintergrund scrollt, Ladephase wirkt eingefroren, „von 4" bei 3 Karten.
**Entscheidung (User):** Direkt aufs Board mit Sichtbarkeits-Garantie — kein Arsenal-Zwischenlager.

## 1. Root Causes (verifiziert)

| # | Befund | Ort |
|---|--------|-----|
| RC1 | **Loadout-Verdrängung:** Board zeigt max. 3 Quests (`QUEST_LOADOUT_CAP = 3`); die Schmiede-Sektion filtert aus diesem gedeckelten Loadout. Sortierung rankt Fokus/Mark/Pin/überfällig/eigene VOR System — angenommene Forge-Quests rutschen unsichtbar ins Quest-Log. Accept wirkt, User sieht nichts. | `data/questPlanning.js:3,140-179`, `components/views/DashboardView.jsx` |
| RC2 | **Fehlende Safe-Areas:** App rendert mit `viewport-fit=cover`; ALLE anderen Vollbild-Overlays nutzen `env(safe-area-inset-*)` — nur das Ritual nicht. X unter der Statusleiste, Accept-Button in der Home-Indicator-Zone (Tap wird geschluckt; „gar nichts passiert" beweist: onAccept feuert nie, sonst würde das Modal unconditional schließen). | `components/ForgeRitualModal.jsx`, `index.html:6`, Muster: `components/FocusMode.jsx:459` |
| RC3 | **Zähler-Mismatch:** `getSelectableCount` = min(Intensitäts-Slots, freie Dailies) — kappt weder auf `proposals.length` noch auf den Loadout-CAP → „von 4" bei 3 Karten und 3 Board-Plätzen. | `data/forge.js:38-47` |
| RC4 | **Kein Scroll-Lock:** Hintergrund scrollt hinter dem Overlay. | `components/ForgeRitualModal.jsx` |
| RC5 | **Ladephase wirkt tot:** statische Dossier-Zeilen, keine Bewegung, keine Zeiterwartung, kein „läuft noch"-Signal. | `components/ForgeRitualModal.jsx` |

## 2. Sichtbarkeits-Garantie (RC1 + RC3)

1. `compareLoadoutQuests` (`data/questPlanning.js`) erhält einen **Forge-Rang**:
   `origin === "forge"`-Quests ranken NACH Fokus, Systemzeichen, Pin und
   Überfällig, aber VOR Chain/eigene/übrige System-Quests. Semantik:
   Explizite User-Prioritäten bleiben oben; frisch Angenommenes ist sonst
   IMMER auf dem Board.
2. `getSelectableCount` (`data/forge.js`) = `min(QUEST_LOADOUT_CAP,
   getDailySystemQuestCount, countManualForgeTargets)` — nie mehr wählbar als
   Board-Plätze existieren.
3. Ritual-Anzeige kappt zusätzlich auf `proposals.length`:
   `n = Math.min(selectableCount, proposals.length)` für Zähler und Toggle-Limit.

## 3. Safe-Area + Layout (RC2 + RC4)

- Kopf: `paddingTop: "max(env(safe-area-inset-top, 0px), 14px)"`; X-Button
  min. 44×44pt Tap-Target, Abstand von der rechten Kante.
- Fuß: `paddingBottom: "calc(max(env(safe-area-inset-bottom, 0px), 12px) + 12px)"`.
- Scroll-Lock: `useEffect` beim Mount — `document.body.style.overflow = "hidden"`,
  Restore beim Unmount; Overlay bekommt `overscrollBehavior: "contain"`.
  (Muster von FocusMode/Tutorial übernehmen, falls dort ein Lock existiert.)

## 4. Lebendige Schmiede-Phase (RC5)

- **Animierter Puls-Ring** um das ⚒-Emblem (CSS-Keyframes, dezent — Opacity/
  Scale, kein Glow).
- **Rotierende konkrete Statuszeilen** (i18n-Array, ~6 Einträge, 3s-Takt,
  Loop): „Analysiere deine letzten Abschlüsse…", „Lese dein Verhaltensprofil…",
  „Prüfe deine besten Aktivzeiten…", „Forme Vorschlag 1 von 3…", „Formuliere
  konkrete Schritte…", „Prüfe Qualität der Vorschläge…". Die Dossier-Zeilen
  bleiben darunter als ruhiger Kontext.
- **Elapsed-Anzeige** (mm:ss) + Erwartungszeile: „Kann bis zu 2 Minuten
  dauern." + Beruhigung: „Du kannst schließen — die Schmiede arbeitet weiter,
  die Karte meldet sich, sobald die Vorschläge bereit sind." (Stimmt technisch
  bereits: Generierung läuft nach Close weiter, Karte zeigt „bereit".)

## 5. Accept-Feedback

Nach erfolgreichem Übernehmen zeigt das Ritual ~1s eine Erfolgs-Phase
(„Übernommen — deine Quests stehen jetzt oben auf dem Board", Häkchen-Moment,
kein Glow), dann `onClose`. Toast bleibt. Kombiniert mit §2 ist das Ergebnis
beim Zurückkommen sofort sichtbar.

## 6. Prompt-Nachschärfung

`GENERATE_QUESTS_PROMPT` (de+en), drei präzisere Regeln (ASCII-de in functions/):
- „doneWhen" muss eine objektiv prüfbare Menge/Dauer/Anzahl enthalten (nie
  „Fertig, wenn du dich besser fühlst").
- „desc" ohne Füllfloskeln; Satz 1 = konkrete Handlung, Satz 2 = konkreter
  Nutzen; niemals Meta-Sprache („Diese Quest…").
- Die 3 Vorschläge müssen sich in Kategorie ODER Aufgabentyp unterscheiden
  (keine 3 Lauf-Varianten).
