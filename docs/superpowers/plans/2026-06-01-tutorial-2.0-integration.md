## Task 6: Fix bugs #1/#2 — skip-button overlap + missing auto-scroll

**Files:**
- Modify: `components/tutorial/TutorialOverlay.jsx`
- Possibly: `data/tutorialSteps.js`, `styles/tutorial.css`

**Root cause (from code review, to confirm in repro):** `getSkipPlacement` chooses the skip corner from the *target/reveal* rect (`nearBottom → "top-left"`), independent of where the *tooltip* lands. On steps `show_quest_board` (06) and `click_create_quest` (07) the target (quest board) is tall and near the bottom, so skip goes top-left; the tooltip for a `position:"top"` step on a tall target gets clamped to `safeTop` (very top), so skip and tooltip collide. There is also no headroom reservation, so `scrollIntoView({block:"center"})` does not free space above the tooltip.

- [ ] **Step 1: Reproduce on an iPhone-sized viewport**

`preview_resize` to ~390×844. Drive the tutorial to step 06 and 07. Screenshot each.
Expected: confirm whether the new 2.0 coachmark still collides with the "Überspringen" button (the user's report). Record the observed overlap. If — and only if — the new coachmark already avoids the collision, skip Steps 2–4 and just verify, then jump to Task 7.

- [ ] **Step 2: Make skip placement tooltip-aware (report tooltip rect up to the overlay)**

In `components/tutorial/TutorialOverlay.jsx`, have `TooltipStep` report its resolved on-screen rectangle to the parent, and choose the skip corner from the *tooltip* band, not the target. Concretely:

- Add an `onLayout` callback prop to `TooltipStep` that fires (in the existing `setTooltipPos`/ResizeObserver effects) with `{ top, left, width, height }` of `tooltipRef.current.getBoundingClientRect()`.
- In `TutorialOverlay`, store it: `const [tooltipRect, setTooltipRect] = useState(null);` and pass `onLayout={setTooltipRect}` to `TooltipStep`.
- Replace the skip placement decision:

```jsx
// Replace: const skipPlacement = isCinematic ? "top-right" : getSkipPlacement(targetRect, revealRect);
const skipPlacement = isCinematic
  ? "top-right"
  : getSkipPlacementFromTooltip(tooltipRect);
```

- Add the helper (tooltip occupies top half → skip bottom; tooltip occupies bottom half → skip top; fall back to target-based logic until the tooltip rect is known):

```js
function getSkipPlacementFromTooltip(tooltipRect) {
  if (!tooltipRect) return "bottom-left";
  const tooltipMidY = tooltipRect.top + tooltipRect.height / 2;
  // Tooltip in the upper half → keep skip out of the way at the bottom, and vice-versa.
  return tooltipMidY < window.innerHeight / 2 ? "bottom-left" : "top-left";
}
```

- [ ] **Step 3: Reserve a safe-zone so the tooltip never clamps under the skip button**

In `getTooltipPosition` (same file), exclude the skip-button band from the tooltip's safe area. The skip button is ~44px tall plus safe-area inset; reserve ~64px on whichever edge the skip sits. Since skip is now derived from the tooltip's own band, reserve symmetric headroom on both edges to keep it simple and stable:

```js
// inside getTooltipPosition, replace the safe constants:
const SKIP_RESERVE = 64; // skip button height + breathing room
const safeTop = 18 + SKIP_RESERVE;
const safeBottom = window.innerHeight - 96 - SKIP_RESERVE;
```

This guarantees the card body cannot reach the corners where the skip control lives, eliminating the overlap regardless of target height.

- [ ] **Step 4: Give real scroll headroom for tall top-anchored targets**

For steps where the target is taller than the available space above it (quest board), scrolling to center does not help. Add a small scroll-margin so `scrollIntoView` leaves room. In the overlay's `updateRects` scroll branch, prefer `block:"start"` for `position:"top"` steps and rely on CSS `scroll-margin-top`. Add to `styles/tutorial.css`:

```css
[data-tutorial='quest-board'],
[data-tutorial='today-command'] {
  scroll-margin-top: 96px;
  scroll-margin-bottom: 140px;
}
```

And in `updateRects`, when `step.scrollTo`, use:
```js
element.scrollIntoView({ behavior: "smooth", block: step.scrollBlock || (step.position === "top" ? "center" : "center"), inline: "center" });
```
(Keep `block:"center"`; the `scroll-margin-*` + the `SKIP_RESERVE` safe-zone do the real work. Only switch a specific step to `scrollBlock:"start"` in `data/tutorialSteps.js` if repro shows it's still cramped.)

- [ ] **Step 5: Re-verify steps 06 + 07 at iPhone width**

Drive to step 06 and 07 again; `preview_screenshot` both.
Expected: the "Überspringen" button and the coachmark are fully separated; the step title ("QUEST BOARD" / "ERSTE QUEST ERSTELLEN") is fully visible; the highlighted target is on-screen with headroom.

- [ ] **Step 6: Commit**

```bash
git commit -am "fix(tutorial): keep skip button clear of coachmark + reserve scroll headroom (steps 6/7)"
```
